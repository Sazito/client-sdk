## `error.type === 'validation'`

Usually indicates missing local prerequisite state:

- no cart credentials before invoice creation
- no invoice credentials before payment actions
- no shipping credentials before address retrieval

## `error.type === 'network'`

Check:

- runtime has `fetch`
- timeout is high enough
- environment can reach Sazito APIs from your deployment network

## Authentication failures

- Confirm `setAuthToken` has been called.
- Ensure backend expects raw JWT in `Authorization` header.

## Debug mode

Enable `debug: true` on both the SDK client and checkout config to print the
complete payment-verification trace:

```tsx
const client = createSazitoClient({
  domain: 'mystore.sazito.com',
  debug: true,
});

<SazitoCheckoutPage
  config={{ debug: true }}
/>
```

The SDK trace covers callback input, credential validation, encoded request,
raw response, proxy/envelope unwrapping, extracted and normalized action,
polling, and pinch finalization. The checkout trace covers callback parsing,
SDK invocation, action routing, and the resulting UI state. Every line shares a
correlation ID such as `callback-...`, while credentials and customer PII are
redacted.
