## Review flow methods

For Profile → Orders feedback, use `getSeed` → `createOrderRating` →
`submitProductReview`.

Show **ثبت دیدگاه** only when both normalized flags are true:
`generalInfo.settings.features.tajrobeEnabled === true` and
`generalInfo.settings.tajrobe.enabled === true`. These correspond to
`features.activate_tajrobe.enabled` and `tajrobe.configurations.enabled` in the
raw general-info response. Require the selected order's non-empty
`orderIdentifier`; never use its display `orderNumber`. There is no order-status
filter in the supplied storefront flow.

For a hosted flow, open `/review/{encodedOrderIdentifier}` on the storefront
origin in a new tab. For your own UI, use the calls below. They reuse the SDK's
configured HTTP client and session; same-origin storefront calls do not establish
cross-origin authentication or CORS guarantees.

### Use the complete flow helper

`feedbacks.submitOrderFeedback(input, options?)` is the shortest safe integration
for a native UI. It loads a fresh seed (or accepts one already loaded by the
host), skips already-submitted orders, creates one order rating, and submits the
selected product reviews sequentially. Build each review with
`buildProductReviewInput(item, commentId, draft)` when you need to use the
lower-level methods yourself.

```ts
const seedResponse = await client.feedbacks.getSeed(selectedOrder.orderIdentifier);
if (seedResponse.error) throw new Error(seedResponse.error.message);
const seed = seedResponse.data;

const result = await client.feedbacks.submitOrderFeedback({
  orderIdentifier: selectedOrder.orderIdentifier,
  orderRate: 5,
  seed, // Reuse the seed rendered by the form; this avoids a second GET.
  reviews: seed.items.map((item) => ({
    item,
    draft: {
      productRate: 5,
      text: 'Great quality.',
      pros: ['Quality'],
      recommendationStatus: 'RECOMMENDED'
    }
  }))
});

if (result.error) {
  // result.error.details.feedback contains commentId and submittedProductCount.
  // Keep the form values and resume product requests; do not create another rating.
} else if (result.data.status === 'already_submitted') {
  // Show the completion state without posting again.
}
```

The helper accepts an empty or partial `reviews` array for UIs where product
reviews are optional. It rejects items that do not belong to the loaded seed or
that are repeated. State-changing requests are sequential and never retried
automatically; a product failure returns progress so the host can resume safely.

### Get Seed

Use: `feedbacks.getSeed(orderIdentifier, options?)`.

Gets review seed data from `/api/v1/feedbacks/seed/{orderIdentifier}`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `orderIdentifier` | `string` | Required | Selected order's `orderIdentifier` token. |
| `options` | `RequestOptions` | Optional | Per-request controls. |

Returns: `SazitoResponse<FeedbackSeed>`.

The identifier is validated and URL-encoded. Seeds are fetched fresh to avoid
reusing stale `hasCommentAlready` state. Malformed seeds and seeds for another
identifier return an `api` error. IDs in the returned seed remain strings;
additional item fields are retained in their original wire format. Spread the
whole selected seed item when submitting its review.

When `hasCommentAlready` is true, show completion without creating another
comment. An empty `items` array is returned as-is: decide how to handle it before
starting a submission; backend completion behavior for empty orders is unconfirmed.

### Create Order Rating

Use: `feedbacks.createOrderRating(input, options?)`.

Submits order-level rating to `/api/v1/feedbacks/comments`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `input.orderId` | `number \| string` | Required | Positive integer order ID from the seed; numeric strings are converted to JSON numbers. |
| `input.orderIdentifier` | `string` | Required | Order identifier from the same seed. |
| `input.orderRate` | `number` | Required | Integer order rate (`1..5`). |
| `options` | `RequestOptions` | Optional | Per-request controls. |

Returns: `SazitoResponse<{ id: string }>` where `id` is `commentId`.

Both credentials are required at runtime. The order ID is sent as a JSON number,
even when the seed exposes it as a string. Invalid input returns a `validation`
error without sending a request. The wire body contains `order_id`,
`order_identifier`, and `order_rate`. An HTTP success without a valid comment ID
returns an `api` error; do not advance or blindly create another rating.

### Submit Product Review

Use: `feedbacks.submitProductReview(input, options?)`.

Submits product review payload to `/api/v1/feedbacks/comments/details`.

| Field | Type | Required / default |
| --- | --- | --- |
| `commentId` | `number \| string` | Required; use the successful store-rating response ID. |
| `productId`, `productVariantId` | `number \| string` | Required positive integer IDs; numeric strings are converted to JSON numbers. |
| `productRate` | `number` | Required integer from 1 to 5. |
| `productName`, `productAttributes`, `productImage`, additional seed fields | Seed item fields | Preserve them by spreading the seed item. |
| `text` | `string` | Optional; defaults to `''`. |
| `pros`, `cons` | `string[]` | Optional; default to `[]`. |
| `recommendationStatus` | `'RECOMMENDED' \| 'NEUTRAL' \| 'NOT-RECOMMENDED' \| 'NONE'` | Optional; defaults to `'NONE'`. |
| `isAnonymous` | `boolean` | Optional; defaults to `false`. |
| `attachmentsServeKeys` | `string[]` | Optional; defaults to `[]`. Only completed non-empty serve keys. |
| `owner` | `boolean` | Optional; defaults to `true` for order feedback. |

Returns: `SazitoResponse<void>`.

Product requests use `comment_id`, numeric `product_id`, and numeric
`product_variant_id`;
the ID/identifier order pair is sent in the preceding store-rating request.
Seed attributes may contain structured values such as color metadata, and seed
images may contain additional fields; these values are preserved in the request.
Submit products sequentially and advance only after each success.

`createOrderRating` and `submitProductReview` force `retries: 0`, including when
request options or global configuration enable retries. Backend idempotency,
duplicate protection, and partial-completion recovery remain unconfirmed. The
SDK does not automatically resume submissions or prevent separate repeated calls.
Keep the returned comment ID and successful product progress in the host UI;
retain inputs and stop on failures. Do not claim completion until every product
submission succeeds. A network failure can have an unknown server outcome.

### Upload Review Images

Use: `feedbacks.uploadReviewImages(images, options?)`.

Uploads review images to `/api/v1/service/filemanager/uploads/public/tajrobe`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `images[].file` | `File \| Blob` | Required | Image file. |
| `images[].name` | `string` | Optional | File display name. |
| `images[].alt` | `string` | Optional | Alt text. |

Returns: `SazitoResponse<{ images: ReviewUploadedImage[] }>` where each image includes `serveKey`.

Wait for uploads to complete, then pass `images.map(image => image.serveKey)` to
the review request. Disable submission while uploads or requests are pending.
The SDK rejects empty files, empty upload lists, and responses without completed
serve keys before the review request is sent. The current storefront request
uses these multipart field names:

```text
images[][file]
images[][name]
images[][alt]
```

`images[][file]` carries the actual bytes. `images[][name]` and `images[][alt]`
are metadata fields; both are optional in `ReviewAttachmentInput`, and the SDK
fills sensible defaults when they are omitted. The field names above are based
on the captured storefront request; the repository does not contain a server
schema that establishes whether Sazito validates either metadata field.

Do not set `Content-Type: multipart/form-data` yourself. The browser must add the
boundary generated for the `FormData` body. A manually copied request that uses
`--data-raw` with empty file sections has no image bytes and will normally receive
a `400` response. To replay an upload with cURL, use `-F` and actual local files:

```bash
curl 'http://localhost:3000/api/sazito/api/v1/service/filemanager/uploads/public/tajrobe' \
  -H 'authorization: YOUR_TOKEN' \
  -H 'x-forwarded-host: your-store.example' \
  -F 'images[][file]=@/path/to/review.webp;type=image/webp' \
  -F 'images[][name]=review.webp' \
  -F 'images[][alt]='
```

The SDK removes caller-provided multipart `Content-Type` headers so `fetch` can
create the correct boundary. Ratings, inputs, error messages, RTL layout, and
accessible controls belong to the host UI.

## Example: End-to-end review submission

```ts
// Check both feature flags before showing the action in your UI.
const seed = await client.feedbacks.getSeed(selectedOrder.orderIdentifier);
if (seed.error) throw new Error(seed.error.message);

if (!seed.data.hasCommentAlready && seed.data.items.length > 0) {
  const orderRating = await client.feedbacks.createOrderRating({
    orderId: seed.data.orderId,
    orderIdentifier: seed.data.orderIdentifier,
    orderRate: 5
  });
  if (orderRating.error) throw new Error(orderRating.error.message);

  // Save this ID and progress in host state; never recreate the rating on a
  // product failure. This loop illustrates a first submission, not recovery.
  for (const item of seed.data.items) {
    const productReview = await client.feedbacks.submitProductReview({
      ...item,
      commentId: orderRating.data.id,
      productRate: 5,
      text: 'Great product.',
      pros: ['Quality'],
      cons: [],
      recommendationStatus: 'RECOMMENDED',
      attachmentsServeKeys: [],
      owner: true,
      isAnonymous: false
    });
    if (productReview.error) throw new Error(productReview.error.message);
  }
}
```

Use the customer's chosen ratings and draft fields in a real UI. Show a thank-you
state after all product submissions succeed, explain that publication follows
store approval, and offer a return action to Orders. If seed loading fails,
show an explicit unavailable state or return to the storefront.
