## Module role in sales flow

`checkout` is the developer-friendly orchestration layer on top of `cart`, `invoices`, `shipping`, and `payments`.

- Use this as the default integration path for MVP checkout.
- It automates cart creation, invoice sync, shipping assignment, and default payment selection.
- Keep module-level APIs (`cart`, `invoices`, `payments`, etc.) for advanced custom flows.

## Methods

### Initialize

Use: `checkout.initialize(input, callbacks?, options?)`.

Runs the full checkout bootstrap flow:

1. Adds item to cart (creates cart if needed).
2. Creates or refreshes invoice.
3. Applies optional discount/comment/invoice-form/credit.
4. Creates optional shipping address and attaches it to invoice.
5. Auto-assigns shipping rates from `itemsShippingRate`.
6. Gets payment methods, picks default (or `paymentTypeId`), creates payment, and initializes payment action.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `input.variantId` | `number` | Required | Variant to add to cart. |
| `input.count` | `number` | Required | Quantity to add. |
| `input.attributes.formAttributes` | `Record<string, any>` | Optional | Product line-item dynamic form values. |
| `input.attributes.schedulerBookingAttributes` | `SchedulerBookingAttributes` | Optional | Booking schedule payload for booking products. |
| `input.shippingAddress` | `ShippingAddressInput` | Optional | Address to create and attach before shipping assignment. |
| `input.discountCode` | `string` | Optional | Discount code to apply on invoice. |
| `input.comment` | `string` | Optional | Invoice note (`addDetails`). |
| `input.invoiceFormAttributes` | `Record<string, any>` | Optional | Checkout-level invoice form data (`invoices.addForm`). |
| `input.useWalletCredit` | `boolean` | Optional | `true` applies wallet credit, `false` removes credit. |
| `input.paymentTypeId` | `number` | Optional | Explicit payment method ID. If absent, default method is used. |
| `callbacks.onSuccess` | `(payload) => void \| Promise<void>` | Optional | Runs when payment action is `showOrder` and final order exists. |
| `options` | `RequestOptions` | Optional | Per-request controls. |

Returns: `SazitoResponse<CheckoutInitializeResult>`.

```ts
const res = await client.checkout.initialize(
  {
    variantId: 12345,
    count: 1,
    attributes: {
      formAttributes: { engraving: 'SDK' },
    },
    shippingAddress: {
      firstName: 'John',
      lastName: 'Doe',
      mobilePhone: '09123456789',
      regionId: 1,
      cityId: 10,
      address: 'No. 10, Example St',
      postalCode: '1234567890',
    },
    useWalletCredit: true,
  },
  {
    onSuccess: ({ order }) => {
      console.log('Order completed:', order.orderNumber);
    },
  }
);

if (res.error) {
  console.error(res.error.details?.step, res.error.message);
}
```

### Process Payment Step

Use: `checkout.processPaymentStep(input, callbacks?, options?)`.

Use this for step-based gateways (for example card-to-card upload/code verification).

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `input.imageUrl` | `string` | Optional | Uploaded payment proof URL. |
| `input.code` | `string` | Optional | Verification code. |
| `input.isFailed` | `string` | Optional | Mark step as failed (`"true"`). |
| `callbacks.onSuccess` | `(payload) => void \| Promise<void>` | Optional | Runs when final order is returned. |
| `options` | `RequestOptions` | Optional | Per-request controls. |

Returns: `SazitoResponse<CheckoutPaymentResult>`.

```ts
const step = await client.checkout.processPaymentStep({
  imageUrl: 'https://cdn.example.com/receipt.jpg',
  code: '894512',
});
```

### Poll Payment Until Settled

Use: `checkout.pollPaymentUntilSettled(callbacks?, options?, intervalMs?)`.

Polls payment action every `intervalMs` milliseconds (default `15000`) until action is not `pending`.

```ts
const settled = await client.checkout.pollPaymentUntilSettled(undefined, undefined, 5000);
```

### Clear

Use: `checkout.clear()`.

Clears checkout credentials for cart, invoice, shipping address, and payment.

```ts
client.checkout.clear();
```

## Known errors

| Type | When it happens |
| --- | --- |
| `validation` | Required prior state is missing (for example invoice/payment credentials) or payment method is unavailable. |
| `api` | Backend checkout step fails or `onSuccess` callback throws. |
| `network` | Transport-level issue or polling/network timeout condition. |
